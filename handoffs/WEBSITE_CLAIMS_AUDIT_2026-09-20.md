1. ~~Admin-gate `tenant-delete` and `tenant-export`~~ **FALSE POSITIVE (coordinator re-check 2026-09-20): both routes already call `hasShop(auth) → requireRole(auth,'admin')` (tenant-delete.js:53, tenant-export.js:31); only the header comment in tenant-delete.js was stale and is now corrected.** Original text: Any authenticated org member — not just an admin — can currently wipe or export an entire shop's data (`api/_lib/routes/tenant-delete.js`, `tenant-export.js` — both literally comment "NOT YET ADMIN-GATED"). Add the same `hasShop(auth) → requireRole(auth,'admin')` guard already used elsewhere (e.g. `keys.js`). This is a live production data-integrity/security hole, not a copy problem.
2. **Fix `privacy.html`'s Stripe status.** It says payments are "planned" / "once payments launch" while Stripe checkout is live in production. A legal document making a false statement about how billing/payment data is handled should be corrected immediately.
3. **Decide on and fix (or remove the claim for) callback tracking.** "Callback dashboards," "$300 callback prevented," and "which techs' jobs generate callbacks" are central to the marketing pitch, but no callback concept exists anywhere in the codebase. Either build a minimal callback flag/metric, or stop making this the headline value prop.
4. **Build or remove: email intake, folder sync, Google Drive sync, CSV/dispatch/accountant export.** Four separate advertised ingestion/export channels (index.html #6, #11, #18) have zero implementation. These are the kind of concrete, checkable claims a prospect or their lawyer can test in five minutes.
5. **Remove "Branch scoping" from the Crew plan, or build it.** No branch/location concept exists in the schema at all; this is a paid-tier feature that flatly does not exist.
6. **Replace the founder bios.** Production HTML still literally renders "Placeholder bio. Add a couple of sentences…" for both founders (index.html:544, :553) — this the kind of thing a visitor screenshots.
7. **Re-verify the AI-auto-verify path live.** Code says `extractDocument.js` should auto-promote to `verified_by='ai'` post-extraction when confident; yesterday's live QA still needed a manual "Verify with AI" click, and double-clicking it produces a contradictory tri-state UI. Confirm which behavior is actually live now and fix whichever is wrong.
8. **Soften or substantiate "Works when the signal drops."** No offline support exists (no service worker, no offline queue). Either scope this claim down to "works on a slow connection" or build minimal offline resilience for the field-tech use case it's specifically sold against.
9. **Turn "Draft outreach" into what it's sold as, or reword it.** It currently copies a plain-text template to the clipboard; the site promises a "drafted... email ready to send." Either wire it to an actual email compose/send flow, or change the copy to "copies a ready-to-paste message."
10. **Add a self-service "export my data" control**, even just on the Billing or Team screen. The backend (`tenant-export.js`) already does the work; today a customer has no way to invoke the promise ("ask us for a full copy at any time") without emailing support and waiting on an engineer to run a manual API call.
