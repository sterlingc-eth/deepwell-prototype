# /api/ask model-free fast path — 2026-09-20

Owner ask: the model costs 1.1-3.4s per question; everything else in
`/api/ask` is ~0.3s (handoffs/ASK_LATENCY_2026-09-20.md). This adds a
model-free fast path that answers common field-lookup questions straight
from `extractions`/entities in ~0.3s with the same citation contract as the
model path, and falls through to retrieval+model for anything it isn't
certain about.

**Reviewer NO-GO fix (same day):** the first cut's intent triggers fired on
generic English sharing a keyword with an intent ("serial killer
documentary", "model of behavior therapy", "who installed the app on this
phone") and, combined with the no-subject whole-tenant fallback, could give a
confident wrong answer on a single-unit/single-customer shop. Fixed by
`classifyIntent` (`fastPath.js`) now requiring, in addition to a trigger
match, either a real extracted subject (address/customer number/serial-or-
model token/name) **or** an independent domain anchor (`hasAnchor` — a short
list of HVAC-equipment nouns with no everyday non-HVAC meaning: condenser,
air handler, furnace, heat pump, RTU, mini-split, package unit, HVAC,
evaporator coil, ductwork, nameplate); a bare trigger word alone (warranty,
serial, model, install(ed), phone, email, address, cost, agreement, permit,
who makes, etc.) is never enough. An earlier draft also anchored on compound
phrases like "serial number"/"model number"/"invoice total" on the theory
that two words were safer than one — adversarial testing disproved that
("what's the model number of my printer" anchors fine on "model number" with
zero HVAC content), so those were removed too; every corpus phrasing that
needed one already carried a real subject instead. `fastPathQuery.js`'s
whole-tenant fallback also now checks `subject.anchored` itself (not just
`!subject.hasAny`) before running, as defense in depth on top of
`classifyIntent`'s own gate. 23 adversarial negatives (the three from the
review plus 20 more, including small talk) were added to
`scripts/verify-fastpath.mjs`; 4 of the 181 positive corpus phrasings needed
adjusting because they were only passing on the loose triggers — see
"Adjusted phrasings" below.

## Files

- `api/_lib/fastPath.js` (new, pure) — intent classification, subject
  extraction, ambiguity resolution helpers, and the answer builders. No `db`,
  no I/O; fully unit-testable.
- `api/_lib/fastPathQuery.js` (new, DB) — resolves a subject to exactly one
  customer/equipment row (or defers), fetches the backing extraction row(s),
  calls back into `fastPath.js`'s builders. Every query is tenant-scoped the
  same way the rest of `recordsStore.js` is.
- `api/ask.js` (edited) — wired in right after the meta-router, before the
  answer cache / retrieval. Adds a `fast` timer stage and a `fast_intent` /
  `fast_hit` log line; on a hit responds `{success:true, data, fast:true}`
  and still writes the `document.queried` audit row; never cached (a fast
  answer is already cheap — see `askCache.js`'s `shouldCache`).
- `scripts/verify-fastpath.mjs` (new, pure, added to `verify:all`) — 181
  corpus phrasings across all 22 intents (asserting intent + extracted
  subject), 6 negative phrasings that must defer, subject-extraction edge
  cases, ambiguity → null, the answer builders (including a computed
  warranty fact with the correct citation and `basis`), stage-eligibility
  parity with the model path, and the `ASK_FAST_PATH=0` disable flag.
- `package.json` (edited) — added `verify:fastpath`, wired into `verify:all`.

No new files under `api/` (still 11 of the 12-file cap). No new
dependencies. No DDL.

## Intent catalogue (22)

`warranty_expires`, `warranty_status`, `model`, `serial`, `manufacturer`,
`install_date`, `installer`, `last_service_tech`, `last_service_date`,
`service_address`, `customer_phone`, `customer_email`, `customer_name`,
`refrigerant`, `tonnage`, `seer`, `filter_size`, `permit_number`,
`invoice_total`, `agreement_term`, `equipment_list`, `document_list_for_subject`.

`seer` and `filter_size` are classified (for the corpus/training purpose)
but have **no backing `extractions.field_key`** (see `extractFields.js`
`FIELD_SPECS` — no field for either exists today) — resolution always
returns `null` for them, so they defer to the model unconditionally. This is
intentional, not a gap to "fix" here: adding a field would mean guessing at
a value shape no document has ever been asked to state.

## Safety rules actually enforced (see `fastPath.js` file header)

1. Ambiguous subject (2+ candidates) → `null` (`pickUnique`), never a guess.
2. Resolved subject with no value for the requested field → `null`, never
   "unknown".
3. Same stage-eligibility as the model path's own `searchExtractions` — no
   stage filter at all (`isStageEligible`, kept as a named function so this
   stays in lockstep if the model path's own rule ever changes).
4. A fast-path exception (bad DB row shape, unexpected error) is caught in
   `api/ask.js` and logged, never a 500 — falls through to retrieval+model.
5. `ASK_FAST_PATH=0` disables classification entirely (`isFastPathEnabled`).
6. Every tenant-scoped query uses the same `tenant_id = current_setting(...)`
   predicate `api/ask.js`'s own meta-router already uses.
7. A computed warranty fact cites the fact the arithmetic ran on
   (`installation_date`) with `basis:"computed"`; a printed one cites the
   printed `warranty_expires` field with `basis:"printed"` — never a
   fabricated page number, matching `answer.js`'s own honesty rules.

## Adjusted phrasings (only passed before because of the loose triggers)

- "When does the Goodman warranty expire?" → "...expire for C-00003?" (had no
  subject and no anchor — "warranty" and "Goodman" alone don't prove this is
  about the tenant's own equipment).
- "What refrigerant does the Goodman take?" → "...take for C-00003?" (same
  reason).
- "What efficiency rating does 1519 W Juniper have?" → "...does the unit at
  1519 W Juniper have?" (no preposition before the address, so nothing was
  actually extracted as a subject — the address regexes require an anchor
  word like "at/on/for/to").
- "What size filter does 1519 W Juniper need?" → "...does the unit at 1519 W
  Juniper need?" (same reason).

## Growing the corpus

The "training" is `TRIGGERS` (intent regexes) + the extraction regexes in
`api/_lib/fastPath.js`, and the phrasing corpus in
`scripts/verify-fastpath.mjs`. To add a phrasing: add a line to `CORPUS`
asserting the intent (and, if it's new, add/extend a trigger regex); run
`npm run verify:fastpath` until it passes. To add a whole new intent: add it
to `FIELD_BY_INTENT` (or `NO_FIELD_INTENTS` if there's no backing field yet),
a `FIELD_INTRO`/`FACT_LABEL` entry, a trigger, and 8+ corpus phrasings.
