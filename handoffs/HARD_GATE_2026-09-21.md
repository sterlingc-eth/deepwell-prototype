# Hard gate: no free preview (2026-09-21)

Owner decision: after sign-up + creating a company, a tenant with no active
subscription ('none'/'canceled') sees ONLY Billing (+ Team/Sign out) until
status is trialing/active/past_due-within-grace. No free preview any more.

## Round 3 — Reviewer NO-GO: background jobs (cron sweep, Inngest queue)
still spent model calls for a billing-gated tenant
- `api/_lib/routes/cron-sweep.js` — `retryOnce()` now calls
  `assertActiveBilling(ctx)` once per call (only when there are documents to
  retry) before touching any of them; a rejection skips the WHOLE tenant for
  that batch — no `ingestDocument` calls, no `recordIngestFailure` (so
  `extract_error` stays untouched) — and logs "billing-gated". New
  `summary.billingGatedTenants` (distinct tenants, deduped across the
  stuck/budget-deferred call sites) surfaces it in the response and the
  `captureMessage` line.
- `api/_lib/queue.js` — both Inngest functions (`read-document`,
  `extract-fields`) re-check `assertActiveBilling(ctx)` in their own
  `step.run`, immediately before the step that would call
  `ingestDocument`/`extractDocumentFields` — a document can sit queued long
  enough for a subscription to lapse after enqueue. On rejection: throws
  `NonRetriableError("billing-gated")` (Inngest marks the run failed once,
  no retry storm) and deliberately skips `recordIngestFailure`, so
  `extract_error` stays `null` and the document is left at whatever stage it
  was already at — indistinguishable from "still waiting its turn" rather
  than "failed", so cron-sweep's own stuck-document sweep picks it back up
  automatically once billing is fixed.
- No new pure decision function: both call sites reuse
  `assertActiveBilling`/`requireActiveBilling` from Round 2, already covered
  by `scripts/verify-billing.mjs`'s none/canceled→402,
  trialing/active/past_due-in-grace→allowed, and lookup-failure→closed/503
  cases. `retryOnce` and the two Inngest closures aren't exported (no new
  branching logic to unit-test in isolation beyond "call the already-tested
  gate, skip on reject"); a true integration test would need a mocked DB/
  Inngest runtime, out of scope for this pure-function verify file.
