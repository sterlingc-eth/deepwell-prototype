# API latency, 2026-09-22

## Round trips, cache-warm (before → after)
- `/api/document-status`: ~7 → ~3
- `/api/account?action=notifications`: ~11 → ~4 (items/count/settings: 3 queries → 1 CTE)
- `/api/upload-url`: ~14+ → ~7 (2 live usage counts now parallel)
- `/api/review`, `/api/warranty-attention`: same shared-cache wins via auth/rate-limit/billing — not restructured directly, see below.

Biggest fixed cost: `requireAuth()` ran `upsertMember()` (resolve_tenant + SET LOCAL + upsert) on every shop-tenant request, unconditionally — now skipped when unchanged in the last 5 min.

## What changed
- **`perf.js`** (new): bounded `TTLCache` + `memoAsync` (in-flight de-dupe). `logStage()` behind `DW_TIMING=1`, one JSON line/stage, no PII/env values.
- **`recordsStore.js`**: `getTenantContext()` — uuid+plan+limits+billing, 5-min TTL, shared by `withTenant`, `rateLimit.js`, `plan.js`; tries SQL `get_request_context()` first, falls back to the 3 old queries if absent (42883). Pool: `keepAlive: true`, `max` 10→**3** (Reviewer NO-GO); warns (never the value) if the connection string isn't Neon's `-pooler` host.
- **`rateLimit.js`**: tenant-resolve + limits-read collapsed into the shared cache; per-minute/daily writes confirmed already single atomic upserts.
- **`plan.js`**: `getCachedBillingRow` — 2 min TTL, re-capped to 30s the instant a fetched row is `'none'`/`'canceled'`.
- **Cache busting (Reviewer NO-GO fix)**: `perf.js`'s `bustTenantCaches()` + `recordsStore.js`'s `bustTenantCache()` clear a tenant from every registered cache; `api/billing.js`'s webhook calls it after `billing_apply()` commits — the only status-changing write path today (a future one, e.g. founder comp, must call it too). **Staleness bound**: busting is same-instance-only; the real cross-instance bound is the TTL — **≤30s** for gated `'none'`/`'canceled'`, **≤2 min** otherwise, **≤5 min** for plan/limits.
- **`upload-url.js`**: billing row from the shared cache; usage counts parallelized.
- **`document-status.js` / `routes/notifications.js`**: full per-request `DW_TIMING` line; notifications' 3 queries → 1.
- **`auth.js`**: upsert-skip cache above; Clerk JWKS already cached in `@clerk/backend`.
- **Client**: `documentClient.ts`/`ingestClient.ts` de-dupe in-flight `upload-url` calls.
- **`M3-config/27-request-context.sql`** (new, optional): one function replaces 3 queries.
